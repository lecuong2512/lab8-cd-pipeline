BẢNG SO SÁNH TÍCH HỢP LIÊN TỤC (CI) vs PHÁT HÀNH LIÊN TỤC (CD)

Kết nối Pipeline Bài 7 (Continuous Integration) → Bài 8 (Continuous Delivery / Deployment)

Lê Việt Cường — DTC235200100
Lớp: KTPM K22A
CI: Checkout → Build → Unit Test → SonarQube → Nexus ⟹ CD: Docker Multi-stage Build → Scan → Push Docker Hub → Deploy & Healthcheck
Tiêu chí CI — Continuous Integration (Bài 7) CD — Continuous Delivery / Deployment (Bài 8)
Mục đích chính Tự động tích hợp, biên dịch, kiểm thử & phân tích chất lượng mã nguồn sớm để phát hiện lỗi ngay khi commit. Đóng gói ứng dụng thành container bất biến, đẩy lên registry và tự động triển khai tới môi trường đích / người dùng.
Đầu ra (Output) Gói biên dịch ci-demo-1.0.0-SNAPSHOT.jar lưu trên Jenkins & Nexus Repository. Docker Image vczo/devops-lab8-app trên Docker Hub & Container Production đang chạy thực tế.
Công cụ sử dụng Git, Jenkins, Maven, JUnit 5, SonarQube, Nexus Repository OSS. Jenkins, Docker (Multi-stage build), Docker Compose, Nginx, Redis, Docker Hub Registry.
Câu hỏi trả lời "Code mới có biên dịch được, vượt qua test và an toàn để merge vào nhánh chính không?" "Bản dựng này đã sẵn sàng đóng gói và triển khai ổn định trên môi trường Production chưa?"
Tần suất kích hoạt Mỗi lần Developer thực hiện git push hoặc tạo Pull Request. Ngay sau khi toàn bộ các giai đoạn CI vượt qua (Quality Gate & Tests PASS).
Ý nghĩa khi thất bại Mã nguồn có lỗi cú pháp, sai logic (Unit Test fail) hoặc vi phạm tiêu chuẩn chất lượng code. Lỗi đóng gói môi trường, lỗi xác thực Registry, xung đột cổng/hạ tầng hoặc Healthcheck sau deploy thất bại.
